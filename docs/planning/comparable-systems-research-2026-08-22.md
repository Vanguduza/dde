## 1. Task & model routing

Maps to blueprint Chapter 6 (Routing Intelligence) and `engine/routing/**` (deterministic policy-table router: gates 0–5 hard elimination, 6–9 reorder-only; `RouteDecision` contract; telemetry in `engine.telemetry`; Route Critic deferred per EDR-0005).

### Top comparable systems

1. **LiteLLM Router** — production load-balancer with cooldowns after failure thresholds, ordered deployment priorities (`order=1 → order=2 → model-level fallback`), context-window-specific fallbacks distinct from generic fallbacks, and background health checks that pull unhealthy deployments from the pool *before* requests fail.
2. **OpenRouter** — cleanly separates two independent decisions: *model selection* vs *provider selection*; provider-layer failover is automatic/on-by-default (deprioritizes providers with outages in the last 30 seconds), while model-layer fallback is an explicit opt-in ordered array that walks once, never loops; "routing is not failover" discipline.
3. **Cursor Router ("Auto", launched July 2026)** — classifier ("Compass") routes per request; a candidate model becomes eligible only when its observed performance clears a one-sided ~75% confidence uplift threshold against the price-efficient baseline; user steers via coarse modes (Cost / Balance / Intelligence) instead of hand-picking models.
4. **GitHub Copilot Auto (HyDRA)** — task-aware routing model trained on where models *actually diverge* (scored pairwise on quality dimensions), combined with a second signal of real-time model health; crucially, it routes only at natural cache boundaries (first turn, after compaction) so switching models never destroys prompt-cache state mid-session.
5. **RouteLLM / NotDiamond / Martian (learned routers)** — RouteLLM shows static rules capture most savings first and learned routers (matrix factorization, BERT-classifier) are an *enhancement layered on top*, calibrated against your own traffic distribution; NotDiamond decides in <60ms; the consensus across 2026 write-ups is: start deterministic, add learned routing only when labeled data exists.

### Adoptable lessons for DDE

- **Add health-based eviction to gate 5.** `engine/routing/rules.py` currently evaluates capacity statically. Adopt LiteLLM's pattern: worker profiles accumulate failure counts in `engine.telemetry` outcome records; N consecutive failures within a window puts a profile in a time-boxed cooldown that removes it at gate 5 (hard-elimination semantics, consistent with Ch.6.1's "removed, not penalised"). Cooldown expiry restores eligibility without policy edit.
- **Separate "same-profile retry" from "different-profile fallback".** OpenRouter's two-layer split maps directly onto DDE: re-dispatching the same WorkerAdapter (e.g., a transient CLI crash) is provider-layer; escalating to a different certified profile is a *policy decision* that should be visible as a distinct `RouteDecision` reason code, walked once in declared order, never looping. Encode fallback chains in the versioned policy table (`policies/routing/deterministic-v1.yaml`) so they are hash-pinned and rollback-able like everything else.
- **Make every route decision carry the served identity + pin for debugging.** Cursor's public criticism thread (reproducibility archaeology when the router silently varies) is the trap to avoid: `RouteDecision` should record the exact profile/version that served, and DDE already does this — keep it mandatory as fallback chains grow, so a mission can always be replayed against the pinned original choice.
- **Cache-aware routing points.** Copilot's insight transfers even though DDE routes tasks not turns: when a TaskAttempt resumes after checkpoint replay or context-package reassembly (`engine/recovery/checkpoint_service.py`, `engine/context/assembly.py`), that boundary is the cheap place to switch worker profile/model; switching mid-attempt invalidates cached prefix state and doubles cost.
- **Uplift-gated escalation, not curiosity-driven exploration.** When Ch.6.7–6.9 learning eventually activates, adopt Cursor's rule: a more expensive profile is eligible only if observed success on that workload class clears a one-sided confidence threshold versus the incumbent — this prevents slow drift toward always-expensive routes and matches DDE's "learning activation staged, not scheduled" stance.
- **Shadow-mode the policy table before promotion.** DDE has `engine/simulation/**` (Routing Simulation Model). Extend scenarios so a candidate policy table runs in shadow over recorded real decisions (`engine.contracts.routing_decision_outcome`) and diffs its choices against production; promote only on measured delta (see flatkey/Skaira release-ring pattern: shadow → 5% canary → full, with pre-registered rollback triggers).

## 2. Context assembly & drift management

Maps to blueprint Chapter 5 (Context Intelligence) and `engine/context/**`: hashed immutable ContextPackages, RRF fusion (`fusion.py`), retrievers lexical/structural/semantic/authority, coverage contracts (`coverage.py`), conflict adjudication (`conflict.py`), budget/eviction, triggered-only Context Critic (`critic.py`), eval corpus (`eval_corpus.py`), knowledge graph (`engine/knowledge/deriver.py`), Project Truth authority (`engine/truth/**`).

### Top comparable systems

1. **Anthropic — "Effective context engineering for AI agents" (Sep 2025)** — codified the attention-budget frame: compaction (summarize near limit, preserve decisions/unresolved bugs, drop redundant tool output), structured note-taking outside the window, sub-agents that burn tens of thousands of tokens but return only 1–2k-token summaries; just-in-time retrieval over upfront loading.
2. **Chroma — Context Rot (July 2025)** — controlled study across 18 frontier models: performance degrades non-uniformly (sometimes sharply) with input length even far below the advertised window; degradation accelerates with lower needle-question similarity and with semantically-similar distractors; coherent haystacks scored *worse* than shuffled ones. Directly validates DDE's small-window curation stance and makes distractor density a measurable quantity.
3. **Cognition — "Don't Build Multi-Agents" (2025) → "Multi-Agents: What's Actually Working" (2026)** — share context and full traces between agents; actions carry implicit decisions, so writes stay single-threaded while extra agents contribute read-only intelligence (clean-context reviewer); Devin Fusion switches models at compaction boundaries so the switch rides a cache miss that would happen anyway.
4. **Aider repo map** — tree-sitter symbol extraction → file reference graph → personalized PageRank biased toward files in play → binary-search fit into a token budget → scope-aware elided rendering. The canonical example of structural retrieval ranked by graph centrality under an explicit token cap.
5. **Letta/MemGPT memory hierarchy** — tiered memory: small editable in-context blocks (persona/human facts), file access, archival semantic search, external RAG; plus sleep-time compute — a background agent consolidates memory during idle periods so the primary agent's context stays clean ("anytime" reads).

### Adoptable lessons for DDE

- **Measure distractor pressure, not just relevance.** Chroma gives DDE a concrete metric for the Context Critic: for each assembled ContextPackage, compute embedding-similarity between retrieved chunks and the task's target intent; flag packages where many high-similarity-but-low-authority chunks coexist with the authoritative needle (the exact configuration that causes sharp degradation). Wire this as a critic finding type in `engine.context.critic` rather than a new subsystem.
- **Treat staleness gates as cache-boundary events.** Cognition's "switch at compaction" + Anthropic's "recently accessed resources survive compaction" translate to: when `engine.recovery.checkpoint_service` replays an attempt, the fresh ContextPackage must be rebuilt (hash changes) — never reuse a stale package hash across a recovery boundary. Make that a contract test in `tests/contract`.
- **Coverage contract ↔ focused-vs-full-history gap.** LongMemEval-style evidence says full-history prompts lose badly to focused prompts. Strengthen `engine.context.coverage` to distinguish "covered because present" from "covered and attended": require the packing order to put authority-ranked content (constitution/EDR excerpts from `engine.truth`) at prompt head and tail, since middle-of-context placement measurably degrades recall.
- **Structural retrieval upgrade path.** Aider's PageRank-over-symbol-graph is a natural evolution of `engine.context.retrievers.structural`: rank repo files by personalized PageRank seeded from the task's touched modules (DDE already knows WriteScopes from `engine.integration.scope`), then binary-search the rendered symbol map into the remaining token budget after authority docs. This is adoptable incrementally inside the existing retriever interface.
- **Budget-aware eviction with decay scoring.** Keep `fusion.py` RRF at k=60 as the robust default (industry consensus: don't tune k before you have ~50–100 labeled queries — which is exactly what `engine.context.eval_corpus` is for), then add per-source weights (authority > derived edges > raw code) before touching k, per production guidance.
- **Sleep-time consolidation analog.** Letta's pattern maps to DDE's triggered-critic philosophy: run knowledge-graph derivation and memory consolidation (`engine.knowledge.deriver`, index lifecycle in Ch.5.4) between missions rather than inline, so mission-time assembly only reads consolidated artifacts.

## 3. Orchestration & durability

Maps to blueprint Chapter 12 (Recovery, effects, durability) and `engine/recovery/**` (`matrix.py`, `checkpoint_service.py`, `replay.py`, `workflow.py`, `dispatch.py`, `states.py`), `engine.events.idempotency.CommandLedger`, `engine.contracts.outbox`, `engine.missions.kernel.py`, `engine.capabilities.lease_service.py`.

### Top comparable systems

1. **Temporal** — the reference for durable execution: deterministic workflow core with non-determinism pushed into retryable Activities; human-in-the-loop as Signal/Update primitives where the workflow suspends at zero compute cost indefinitely; durable timers make approval timeouts part of the persisted history; complete event-history audit trail; used by Replit Agent 3, OpenAI Codex web, and long-running automation at Cursor.
2. **DBOS** — Postgres-as-orchestrator: workflows/steps checkpointed as single Postgres writes in the same transaction as business writes (exactly-once by construction); no new failure domain; per-tenant queue concurrency controls built in; known limits are Postgres contention (WAL pressure, autovacuum on history tables).
3. **Inngest** — event-driven step functions (`step.run` memoization = durability) with best-in-class flow control: concurrency limits, throttling, debouncing, rate limiting, prioritization per function — "the knobs that keep a swarm of agents from stampeding rate-limited APIs."
4. **Restate** — journal-based exactly-once via virtual objects (per-key serialized handlers); single Rust binary, low ops footprint; durable approval modeled as an "awakeable" with dedup keys so a double-delivered approval cannot double-resume.
5. **Hatchet** — Postgres-first task queue + workflow; proof that DDE's chosen substrate can carry orchestration-grade durability without adding infrastructure.

### Adoptable lessons for DDE

- **Approvals are durable events, not UI callbacks.** Every platform converged here: approval = suspend-until-signal with (a) dedup key (second delivery of the same approval must be idempotent — DDE already has CommandLedger; extend approval intake through it), (b) a persisted deadline with a defined escalation path (auto-deny, never auto-approve, per safety guidance), (c) zero-cost suspension. Concretize in `engine.governance.service` + `engine.contracts.approval`: approvals get idempotency keys and expiry, checked at the mutation site.
- **Watchdog/reaper for stuck attempts.** Temporal's durable timers imply DDE needs a reaper: attempts whose lease expired but whose state didn't transition (`engine.workers.states`, `engine.capabilities.lease_states`) get swept by a periodic reconciliation pass driven off `engine.recovery.matrix`. The matrix should gain explicit rows for "lease expired mid-run" and "worker silent past heartbeat deadline."
- **Flow control belongs in the spine.** Inngest's lesson: per-workload-class concurrency caps and throttling in `engine.execution.policy` prevent parallel missions from stampeding provider rate limits — pair with LiteLLM-style RPM/TPM awareness so gate 5 (capacity) reads live counters, not config guesses.
- **Crash-recovery tests at worst-case moments.** Zylos' durable-execution survey: "recovery tests that intentionally crash the runtime at the worst possible moments." DDE has `tests/recovery`; extend it to inject crashes between outbox write and dispatch, between effect execution and checkpoint, and mid-approval-wait — asserting no duplicate side effects (Ch.12's UNKNOWN rule: never blind-retry; verified absence permits new mutation).
- **Postgres contention hygiene now, not later.** DBOS operators hit WAL pressure and autovacuum problems on hot history tables. DDE's append-only tables (Ch.3.7 partitioning/retention) should get partitioning + retention jobs *before* volume, since DDE shares DBOS's architecture (single Postgres, transactional outbox).
- **Keep the no-framework stance, steal the primitives.** AGENTS.md forbids introducing an agent framework/graph runtime for core state — correct call given DBOS/Hatchet prove the primitive set (checkpoint, journal, dedup signal, durable timer, queue) is implementable directly on Postgres. The lesson is the primitive checklist, not a dependency.

## 4. Verification & acceptance oracles

Maps to blueprint Chapter 11 and `engine/verification/**` (`runner.py` executes DDE-declared literal commands — generator/verifier independence by construction; `oracle.py`, `mission_oracle.py` for wrong-product detection; `checks.py`), `engine.attribution.service`, `engine.integration.gates`, `tests/contract`, golden mission fixture.

### Top comparable systems

1. **SWE-bench harness lineage (Verified → Pro, and its documented failure modes)** — FAIL_TO_PASS/PASS_TO_PASS structure is the right shape for task acceptance, but 2025–2026 audits found: future-repo-state leakage (fixed by scrubbing reflogs/branches/tags), test-file overwrite exploits (agent patch adds a file at a test_patch path → false positive "resolved"), overly strict tests enforcing implementation details, and underspecified prompts. Harness integrity is a first-class attack surface.
2. **Anthropic — "Demystifying evals for AI agents"** — three grader layers (session outcome, trace quality, tool-call correctness); choose deterministic graders wherever possible, LLM graders where necessary, humans sparingly; give LLM judges an explicit "Unknown/insufficient information" escape; grade each rubric dimension with an isolated judge; calibrate judges against expert humans periodically.
3. **Google TAP presubmit/postsubmit design** — presubmits run only fast reliable tests (best-effort, ML-selected); postsubmit runs comprehensive affected-tests periodically with automated culprit-finding; flaky handling via quarantine hotlists and Presubmit Rescue (an ML model that predicts whether a failed execution was a flake and auto-ignores it while keeping the test visible for repair).
4. **PBT-Bench / PROBE (property-based testing at agent scale)** — agents derive semantic invariants from documentation and craft Hypothesis strategies concentrating input mass on trigger regions; PROBE hardens weak properties adversarially by generating counter-implementations that satisfy the property but violate intent (+9.79% mutation score). Property tests catch what example tests miss in generated code.
5. **OpenAI/Aetos coding-eval critique** — single end-to-end pass rates hide harness variance (harness choice swings cost and pass rate materially); component-level diagnostics and methodology disclosure matter more than headline numbers.

### Adoptable lessons for DDE

- **Anti-gaming checks belong in `runner.py`'s chain, not policy docs.** SWE-bench issue #538 is precisely DDE's threat model (a worker that edits its own tests). Add mechanical checks before oracle evaluation: (a) diff-touched-files ∩ declared test files for the task must be empty unless the task explicitly authorizes test changes; (b) any file added at a path matching the oracle's expected-test layout is rejected; (c) record these as `Evidence.independence_flags` entries (pattern already exists in `runner.py`). These are cheap, deterministic, and close the "worker grades its own homework" hole.
- **Scrub future state in workspaces.** Adopt SWE-bench v4.1's fix in `engine.workspaces.git`: when provisioning verification workspaces, strip reflogs, non-task branches, and tags so neither implementation nor verification workers can read solution-bearing history. Contract-test it.
- **Two-tier verification mirroring Google TAP.** Per-task acceptance (fast, deterministic checks only — `engine.verification.checks`) at attempt close; comprehensive mission-level suite (slower, includes `mission_oracle.py` wrong-product detection) post-merge-queue-entry in `engine.integration.gate_service`, with automated culprit attribution via `engine.attribution.rules`. Flaky-check quarantine: a check failing intermittently (N flakes in M runs in `engine.telemetry`) gets auto-flagged, excluded from blocking, and tracked to repair — never silently deleted.
- **LLM-judged criteria need judge discipline.** Where AcceptanceOracle uses model judgment (open-ended acceptance criteria), apply Anthropic's rules: isolated judge per criterion dimension, categorical integer rubric with explicit anchors, mandatory reasoning-before-verdict, structured JSON output, an explicit INSUFFICIENT-EVIDENCE verdict that maps to UNKNOWN (feeding Ch.12's recovery rule rather than a false PASS/FAIL), and periodic calibration against held-out human-labeled cases stored in the eval corpus.
- **Property-based checks as an oracle check type.** Add a PBT check kind to `checks.py`: for pure functions touched by the diff, generate roundtrip/invariant/idempotency properties and run bounded Hypothesis campaigns in verification. PROBE's adversarial refinement (generate counter-implementations that pass the property) is the quality bar for accepting a generated property — reject properties a deliberately-buggy mutant satisfies.

## 5. Mission-control UX / front-end design

Maps to `interfaces/dde-studio/**` (VS Code extension: `shared/ui/overview.ts`, `panels.ts`, `missionControl.ts`, `base.ts`, `html.ts`; connection layer `src/connection/gatewayClient.ts`, `studioGateway.ts`, `cliTransport.ts`, `healthClient.ts`; desktop shell `desktop/src/shell.ts`), gateway surface in `engine.gateway.api`, attention items (`engine.contracts.attention_item`), governance approvals.

### Top comparable systems

1. **Langfuse agent graphs** — dual view of one trace: Aggregated (unique steps collapsed with counters, loops drawn as cycles — "what does this agent do") vs Expanded (every call unrolled in execution order — "where exactly did it go wrong"); deterministic layout so the same trace always draws the same way; observations table with saved filtered views.
2. **Temporal Web + OTel-linked traces** — workflow/event-history UI as system of record; Langfuse/TemporaI integrations show the pattern of linking durable-execution spans (`temporalWorkflowID` attributes) into one nested trace spanning client→workflow→activity→LLM call; noted limitation: Temporal's UI speaks engine primitives, not agent concepts (turns, costs, tool outcomes) — a caution about vocabulary.
3. **Linear design language** — keyboard-first with Cmd+K command palette as universal entry (fuzzy search, shortcuts shown beside actions); optimistic UI with sub-100ms interaction target; density with receding chrome; 120–180ms motion as state-change feedback; the meta-lesson: lift the interaction discipline, not the visual skin.
4. **AI action-review / approval-flow patterns (uipotion, StackAI, dev.to/multigrid, NN/g UXtigers)** — propose-then-commit with evidence packs tuned for a 10–30 second decision; progressive disclosure ("bench vs drawer": outcome + decision-critical action on top, full trace one click away); render the *resolved* action (actual diff, actual recipients), never a paraphrase of the request; risk tiers with non-color indicators; plan-level approval requires re-scoring resolved parameters at execution time (stop if a step resolves into a higher tier than the plan implied).
5. **smolagents GradioUI / OTel instrumentor** — minimal live view (thoughts + tool calls streaming, interrupt button) plus standard OTel export for deep inspection; proves a thin live surface + rich backend traces beats building a heavy bespoke dashboard.

### Adoptable lessons for DDE

- **Approval panels must show resolved parameters, not intent text.** For `attention_item` approvals in dde-studio: render the concrete diff, the resolved capability scope, the exact commands the verification chain will run, and reversibility class (from `side_effect_class`). Add the multigrid rule to `engine.governance.service`: if an approved plan step resolves at execution time into a stricter tier, pause and re-request — plan approval alone is unsafe.
- **No batch-approve across risk classes.** Batch approval is a documented operator-error vector. Allow multi-select approve *only* for items sharing the same side-effect class and risk tier; anything destructive/external-facing is single-item with typed confirmation. Enforce server-side in the gateway (`engine.gateway.commands`), not just in the UI, so API clients inherit the rule.
- **Aggregated/Expanded toggle for mission timelines.** Copy Langfuse's dual view for the mission overview panel: default aggregated (tasks collapsed by name with attempt counts, retry loops drawn as cycles), expanded per-attempt trace for debugging. Deterministic layout keeps operator muscle memory valid.
- **Attention budgeting via tiered interruption.** UXtigers' slow-AI pattern maps to DDE's attention items: true blockers interrupt (badge/status bar via `statusBar.ts`), milestones digest into a summary, everything else archives into a resumption brief ("what ran, what it cost, what needs you"). dde-studio's overview panel should open onto the resumption brief after long mission gaps.
- **Keyboard-first operator surface.** Adopt Linear's discipline in the extension/webview: Cmd+K palette for navigate-to-mission/approve/reject/open-trace, shortcuts displayed beside actions, optimistic status flips with rollback toast. Sub-100ms local interactions; the gateway client (`gatewayClient.ts`) should never block UI on round-trips for view state.
- **Trace linkage IDs end-to-end.** Follow the Temporal↔Langfuse attribute convention: every studio view carries the mission/task/attempt correlation IDs so one click jumps from panel row → gateway trace → audit ledger entry (`engine.audit`). The ID plumbing matters more than charting polish.

## 6. Operational safety when shipping agent systems

Maps to `engine/capabilities/**` (descriptors, leases, broker, `taxonomy.py` side-effect classes), `engine.governance.config`, `engine.audit.ledger`, `engine.environments.backends` (execution isolation), credential handles (`engine.contracts.credential_handle`), Ch.14 security chapters.

### Top comparable systems

1. **Simon Willison — lethal trifecta (June 2025)** — private data + untrusted content + external communication in one execution path ⇒ exploitable via indirect prompt injection; defense is breaking at least one leg structurally (dual-LLM quarantine, egress allowlists, least privilege), because filtering prompts doesn't work; key refinement: draw the three legs along the *content's path*, not per component — pipelines assemble the trifecta across stages that are individually innocent.
2. **Kill-switch engineering consensus (2025–2026 practitioner guidance)** — a real kill switch is infra-level credential revocation checked *before every tool call* (~1ms kill-flag poll in the orchestrator), not a UI button or a prompt instruction; pair with compensating transactions for partial states after a stop; auto-deny (never auto-approve) on approval timeout.
3. **Cost-control playbook (runaway-loop economics)** — layered budgets: provider console caps (blunt), gateway-level dollar budgets per team/run (real-time enforcement before invoice), session budgets, retry caps (each retry resends full context — retries multiply tokens, not just calls), circuit breaker tripping after N consecutive violations requiring manual reset, alert thresholds at 50/80/100% of budget. Documented incident: $47k runaway loop; DN42 agent $6.5k overnight.
4. **Audit-trail-as-causal-commit-log (permit.io, thomasthelliez, ARMO)** — bind identity + intent + policy version + decision + obligations + outcome + correlation/causation IDs in one append-only schema; log denials as first-class structured events (denial logs are the best early prompt-injection signal); tamper-evidence via hash chaining; test: reconstruct any decision from 30 days ago in under an hour.
5. **Guild/NHI-scale least privilege** — RBAC breaks for agents; grant per-endpoint scopes starting from the smallest plausible set and expand only when the denial log shows a consciously-authorizable need; daily token-budget caps enforced in the control plane; nothing happens outside the supervised boundary.

### Adoptable lessons for DDE

- **Trifecta review per execution path.** Add a charter-review question: for each capability composition a worker can reach (implementation adapter + workspace + git push + telemetry egress), name which leg of the trifecta is broken. Concretely: `engine.capabilities.broker.provider` should enforce egress allowlists per capability descriptor; workers processing retrieved untrusted content (issue text, web-fetched docs) must hold no exfiltration-capable lease simultaneously — expressible as a lease-conflict rule in `engine.capabilities.lease_service` alongside existing scope conflicts.
- **Kill flag at the mutation site.** Add a revocation token consulted inside the same transaction/check that guards every side-effecting capability invocation (broker admission path), not merely at attempt start. Revoking a principal grant (`engine.contracts.principal_grant`) must take effect before the next tool call, within one lease heartbeat. Test: revoke mid-run, assert the next mutation is refused and the attempt lands in the recovery matrix as INTENTIONALLY_STOPPED (not FAILED — attribution differs).
- **Budgets as first-class mission parameters.** Give ExecutionPlan (Ch.7.1) explicit token/dollar ceilings per mission and per attempt, decremented at each worker dispatch and LLM-bearing verification step; exceeding ceiling raises a typed error mapped to the error contract (no silent overrun), trips the mission into a paused-for-human state, and surfaces as an attention item. Retry policy must count token cost, not call count.
- **Denial telemetry as security signal.** Every capability/admission denial in the broker writes a structured audit event (policy id, reason code, attempted scope) into `engine.audit.ledger`; dashboards track denial spikes — the cheapest working prompt-injection detector per Guild's operational experience.
- **Hash-chain the audit ledger.** DDE already has `engine.audit.ledger` and canonical hashing utilities (`engine.core.hashing`): chain audit entries (each entry hashes the previous) and periodically pin the tip externally (even a CI-published digest) so post-hoc modification/truncation is detectable — matching EU-AI-Act-style traceability expectations landing in 2026.
- **Rehearse the incident.** A quarterly game-day script: runaway mission (budget breach), injected instruction in retrieved content (trifecta probe), killed worker mid-side-effect (UNKNOWN reconciliation). Each drill must exercise the actual kill switch, the actual ledger, and the actual recovery matrix rows — a control that has never been rehearsed is a claim, not a control.

## Prioritized top 10 improvements

Mixing correctness (preventing operational errors) with capability gains. Correctness items come first — DDE's own history (mission-chapter-gate rule) says unenforced controls are how missions fail.

1. **Worker self-grading guardrails in the verification chain** (correctness; §4). Mechanical anti-gaming checks in `engine.verification.runner.py`: forbid undeclared edits to test/oracle-owned paths, reject patches that shadow expected test files, record results as `Evidence.independence_flags`. Small, deterministic, closes the highest-severity trust hole.
2. **Kill flag checked at every side-effecting mutation site** (correctness; §6). Revocation token consulted in the broker admission path and lease checkout, effective within one heartbeat; mid-run revocation lands as a distinct recovery-matrix state. Without this, every other safety control depends on the agent cooperating.
3. **Mission/attempt budgets with typed exhaustion errors** (correctness; §6). Token/dollar ceilings in `ExecutionPlan`, decremented at dispatch, surfaced in dde-studio; exhaustion pauses-for-human rather than silently continuing. Runaway cost is the most common production agent failure mode.
4. **Health-based eviction + two-layer fallback in the router** (capability, correctness-adjacent; §1). Failure-count cooldowns feeding gate 5 in `engine.routing.rules.py`; declared, hash-pinned fallback chains in the policy table distinguishing same-profile retry from cross-profile escalation; served identity pinned in every `RouteDecision`.
5. **Durable approvals: dedup keys + persisted deadlines + auto-deny** (correctness; §3). Approval intake through `CommandLedger` for idempotency; expiry with escalation in `engine.governance.service`; gateway-enforced no-batch-approve-across-risk-tiers rule; re-scoring of resolved parameters against approved tiers at execution time.
6. **Workspace future-state scrubbing** (correctness; §4). Strip reflogs/branches/tags when provisioning verification workspaces (`engine.workspaces.git`) so neither generator nor verifier can read solution-bearing history; contract-test it.
7. **Flaky-check quarantine + two-tier verification cadence** (capability; §4). Telemetry-driven flake detection in `engine.telemetry` excluding quarantined checks from blocking while tracking them to repair; fast deterministic per-task acceptance vs comprehensive mission-level oracle post-merge-queue.
8. **Shadow-mode policy promotion pipeline** (capability; §1). Candidate routing policy tables evaluated in `engine.simulation.scenarios` over recorded real decisions, promoted on measured deltas with pre-registered rollback triggers — the safe path toward Ch.6 learning without risking live missions.
9. **Distractor-pressure metric for the Context Critic** (capability; §2).
